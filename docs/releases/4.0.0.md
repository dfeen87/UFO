# Version 4.0.0 — BEDROCK engineering baseline

Version 4 is a major engineering-baseline release. The existing radial
membrane, governor, routing, semantic-memory, agentic, and federated-shard
architecture remains intact; the guarantees underneath its lowest-level
numeric and trust boundaries are now explicit and permanently exercised by CI.

The project uses the major increment as a release milestone. It also contains
behavioral-contract tightening: inputs that previously could carry non-finite
state or malformed shard evidence are now rejected. No sound public workflow
or architectural layer was intentionally removed.

## Explicit invariants and corrected failure behavior

- Every numeric field in a `BehavioralString` must be finite in addition to
  satisfying its documented range. Membrane baseline cost must be finite and
  non-negative, and Gaussian basis width must be finite and positive. This
  prevents NaN from bypassing ordinary less-than comparisons and contaminating
  geometry.
- Activation updates validate the complete candidate vector before committing
  any element. Wrong-shaped or non-finite deltas fail without partially
  changing the membrane.
- Governor coefficients must be finite. A non-negative NaN is not a meaningful
  control weight and can no longer enter Lyapunov or propagation calculations.
- Federated shard admission fails closed when shard evidence or workload
  requirements are unknown, boolean, non-numeric, non-finite, or negative.
  Unknown workload keys are rejected instead of being silently ignored. This
  closes the IEEE-754 NaN comparison path that could otherwise authorize a
  shard with malformed trust, policy, capacity, privacy, latency, or cost data.

These changes deliberately reject malformed states that Version 3 could
accept. Callers providing finite, documented inputs retain the same behavior.

## Regression and CI guarantees

The BEDROCK regression suite covers non-finite model construction, atomic
activation rejection, non-finite governor configuration, malformed shard
state, malformed workload requirements, negative requirements, and unknown
evidence fields. Tests assert public behavior and post-failure state rather
than private implementation details.

CI now installs the project itself, runs the actual `radial_membrane_ai` test
suite with coverage attributed to the correct package, performs lint and type
checks without failure-masking dependency installation, builds distribution
artifacts, imports the installed package, verifies the authoritative version,
and smoke-tests the installed `ufo` entry point. The CLI is declared in the
standard project metadata used by the setuptools build backend.

## Validation boundary

This repository remains a research-grade governed simulation. Unit,
integration, packaging, and CLI checks demonstrate software behavior only;
they are not hardware validation, operational safety approval, AI alignment
certification, or production certification. External adapters, deployed
policy sources, real hardware, concurrency under production load, and
domain-specific operating envelopes require independent integration and
system validation before operational use.
